# نبض | حسابداری شخصی

برنامهٔ سبک حسابداری شخصی با Rust، رابط فارسی راست‌چین، فونت فارسی Vazirmatn تعبیه‌شده، تاریخ شمسی و ذخیره‌سازی محلی SQLite.

## ویژگی‌ها
- ثبت درآمد و هزینه به تومان
- نسخهٔ فروشگاهی: کالا، SKU و بارکد، سبد فروش و کسر موجودی
- ثبت فاکتور خرید و افزایش موجودی به‌صورت تراکنشی
- ثبت مشتری و تأمین‌کننده، ثبت هزینه‌های فروشگاه و گزارش فروش/خرید/هزینه
- خروجی CSV فروش‌ها و پشتیبان‌گیری محلی از پایگاه داده
- تاریخ شمسی و ارقام فارسی
- دسته‌بندی و یادداشت تراکنش
- جست‌وجو، حذف، و جمع درآمد/هزینه/خالص
- ذخیره‌سازی محلی در `~/.local/share/nabz/nabz.sqlite3`
- بدون نیاز به حساب کاربری یا اینترنت هنگام اجرا

## ساخت خروجی‌های دسکتاپ و Raspberry Pi (در صورت نیاز)

برای جلوگیری از مصرف بی‌مورد GitHub Actions، بسته‌های نصب‌شدنی به‌صورت خودکار ساخته نمی‌شوند. ساخت هر نسخه فقط با اجرای دستی workflow مرکزی انجام می‌شود:

[Build selected Nabz packages](https://github.com/herotux/Nabz/actions/workflows/build-selected-packages.yml)

در صفحهٔ workflow روی **Run workflow** بزن و از گزینهٔ **Choose exactly which package(s) to build** یکی از این موارد را انتخاب کن:

| گزینه | خروجی |
|---|---|
| `desktop-slint` | نسخهٔ بومی Slint برای Linux دسکتاپ x86_64 |
| `desktop-tauri` | نسخهٔ Tauri برای Linux دسکتاپ x86_64 (deb و AppImage) |
| `raspberry-slint` | نسخهٔ بومی Slint برای Raspberry Pi OS شصت‌وچهاربیتی ARM64 |
| `raspberry-tauri` | نسخهٔ Tauri برای Raspberry Pi OS شصت‌وچهاربیتی ARM64 (deb) |
| `all` | ساخت هر چهار خروجی |

پس از پایان موفق اجرا، فایل‌ها در بخش **Artifacts** همان اجرای workflow قرار می‌گیرند. برای صرفه‌جویی، فقط job مربوط به گزینهٔ انتخاب‌شده اجرا می‌شود؛ گزینهٔ `all` هر چهار job را اجرا می‌کند.

**نکته:** بیلد Tauri روی Raspberry Pi با runner معماری ARM64 انجام می‌شود و بستهٔ deb تولید می‌کند؛ سازگاری نهایی باید روی مدل و سیستم‌عامل واقعی رزبری‌پای آزمایش شود. نسخهٔ Slint نیز هنوز در حال توسعه است. قبل از آزمایش با اطلاعات واقعی، از دیتابیس نسخهٔ پشتیبان بگیر.

Workflowهای قدیمی ساخت Linux، Tauri و Raspberry Pi برای سازگاری باقی مانده‌اند اما فقط دستی اجرا می‌شوند. برای ساخت‌های جدید از workflow مرکزی بالا استفاده کن.

## ساخت از سورس
نیازمندی‌ها: Rust stable و وابستگی‌های توسعهٔ لینوکس برای `eframe`.

```bash
./scripts/fetch-font.sh
cargo test
cargo run --release
```

## تست‌ها
تست‌های واحد برای تبدیل تاریخ میلادی به شمسی، اعتبارسنجی تاریخ شمسی، ارقام فارسی و قالب‌بندی مبلغ در `cargo test` اجرا می‌شوند. هر push و pull request در GitHub Actions بررسی و ساخته می‌شود.

## حریم خصوصی
اطلاعات حسابداری به‌صورت محلی ذخیره می‌شوند و برنامه آن‌ها را به سرور ارسال نمی‌کند.

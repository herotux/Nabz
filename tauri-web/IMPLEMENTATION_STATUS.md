# وضعیت پیاده‌سازی نبض — شاخهٔ اصلی `main`

آخرین بررسی: 2026-10-28

## وضعیت بیلد و انتشار

- شاخهٔ `main` اکنون نسخهٔ Tauri 2 در پوشهٔ `tauri-web/` را به‌عنوان مسیر اصلی توسعه نگه می‌دارد.
- Workflow اصلی `.github/workflows/tauri-web-ci.yml` روی push به `main` و `tauri-web-prototype`، روی pull request و به‌صورت دستی اجرا می‌شود. آیکون PNG معتبر در زمان CI تولید می‌شود و وابستگی `libfuse2` برای AppImage نصب می‌شود.
- Workflow شامل نصب وابستگی‌های Linux، ساخت آیکون PNG معتبر، بررسی TypeScript/Vite، اجرای تست‌های Rust/SQLite، ساخت بسته‌های AppImage و deb و بارگذاری artifact است.
- **وضعیت CI آخرین تغییر: تأییدنشده.** در ابزارهای در دسترس این نشست امکان فهرست‌کردن مستقیم تمام اجرای push-triggered وجود نداشت؛ بنابراین نتیجهٔ سبز یا artifact واقعی را ادعا نمی‌کنیم.
- نصب، اجرای مجدد و smoke test روی Manjaro واقعی هنوز تأیید نشده است.

## تصمیم‌های طراحی

- نسخهٔ دسکتاپ مرجع طراحی است؛ تغییر ظاهر فقط برای رفع مشکل یا تکمیل جریان واقعی انجام شود.
- پیاده‌سازی فعال در `tauri-web/` است؛ کد قدیمی egui از مسیر اصلی تغییرات رابط Tauri جدا نگه داشته می‌شود.

## قابلیت‌های پیاده‌سازی‌شده در کد (نیازمند تأیید اجرایی)

- هشت صفحهٔ اصلی: داشبورد، طرف‌حساب‌ها، فاکتورها، دریافت و پرداخت، کالا و انبار، گزارش‌ها، چاپ و بارکد، تنظیمات.
- SQLite محلی در مسیر دادهٔ برنامه، با جدول‌های طرف‌حساب، کالا، فاکتور، ردیف فاکتور، دریافت/پرداخت و تنظیمات.
- فرمان‌های Tauri برای ثبت/خواندن اطلاعات، گزارش‌ها، پشتیبان‌گیری و بازیابی.
- ثبت فاکتور در تراکنش SQLite، کنترل موجودی فروش و افزایش موجودی خرید.
- تخصیص دریافت/پرداخت به مانده‌های باز و ماندهٔ افتتاحیه، بر اساس FIFO برای فاکتورهای باز.
- اعتبارسنجی ساختار پشتیبان JSON پیش از شروع تراکنش بازیابی.
- پیش‌نمایش بارکد Code 39 و چاپ از طریق گفت‌وگوی چاپ مرورگر؛ چاپ مستقیم و اتصال سخت‌افزار پیاده نشده است.
- تاریخ سربرگ با قالب تقویم هجری شمسی نمایش داده می‌شود.

## محدودیت‌ها و ریسک‌های شناخته‌شده

- داده‌های نمونهٔ فروشگاه از فهرست‌ها، آمار اولیهٔ داشبورد و گزارش‌ها حذف شده‌اند؛ کارت‌ها و فهرست کالا پس از خواندن SQLite به‌روزرسانی می‌شوند. هنوز همهٔ جزئیات و گردش‌های حساب به‌صورت کامل پیاده نشده‌اند.
- ویرایش کامل طرف‌حساب، کالا و فاکتور پیاده نشده است.
- فروش کالای ثبت‌نشده اکنون رد می‌شود و تست rollback آن اضافه شده است؛ فاکتور خدماتی هنوز پشتیبانی نمی‌شود.
- روش ارزش‌گذاری موجودی/بهای تمام‌شده هنوز حسابداری کامل (مانند FIFO هزینه‌ای) نیست؛ قیمت خرید کالا با آخرین خرید به‌روزرسانی می‌شود.
- ماندهٔ افتتاحیهٔ منفی اکنون تا زمان تعریف روشن جهت بدهکار/بستانکار رد می‌شود؛ ماندهٔ طرف‌حساب دوگانهٔ غیرصفر نیز رد می‌شود. برای این قواعد تست اضافه شده، اما اجرای CI هنوز تأیید نشده است. پیش‌پرداخت و برگشت از خرید/فروش همچنان به پیاده‌سازی و تست نیاز دارند.
- چاپ فاکتور کامل، اسکنر USB-HID، استفاده از گوشی به‌عنوان بارکدخوان و نسخهٔ Raspberry Pi تکمیل نشده‌اند.
- تا زمان سبزشدن CI، مشاهدهٔ artifact و اجرای smoke test روی Manjaro، نسخه برای استفادهٔ حسابداری واقعی تأییدشده محسوب نمی‌شود.

## گام بعدی

1. تأیید اجرای CI و رفع خطاهای واقعی.
2. نصب و اجرای بسته روی Manjaro و بررسی حفظ داده پس از restart.
3. رفع ریسک‌های صحت حسابداری و افزودن تست‌های هدفمند.
4. حذف داده‌های نمونه از مسیرهای عملیاتی و اتصال همهٔ فهرست‌ها/کارت‌ها به SQLite.
5. تکمیل ویرایش، گردش کالا/حساب، چاپ و پشتیبان‌گیری پیش از انتشار.

# وضعیت پیاده‌سازی نبض — React/Tauri

آخرین بررسی: 2026-11-17  
شاخهٔ مرجع: `ui/react-tauri-redesign` — [PR شمارهٔ ۸](https://github.com/herotux/Nabz/pull/8) (Draft)

## خلاصهٔ وضعیت

- مسیر محصول: React + TypeScript + Vite + Tauri 2 + Rust + SQLite.
- هستهٔ مالی `crates/nabz-core` به backend Tauri متصل است.
- schema دیتابیس: نسخهٔ ۱۰.
- فاز صفر: تثبیت معماری و workflowهای Arch انجام شده.
- فاز یک: migration تا v10، تخصیص دریافت/پرداخت، دفتر ابطال، snapshotهای COGS، برگشت/ابطال، import امن دیتابیس egui و پشتیبان‌گیری JSON v2 پیاده‌سازی شده‌اند؛ نتیجهٔ CI آخرین commit هنوز در انتظار است.
- این وضعیت به معنی تأیید استفادهٔ مالی روی دستگاه واقعی نیست؛ نصب واقعی Manjaro و آزمون چاپگر/بارکدخوان هنوز انجام نشده است.

## CI و بسته‌بندی

- frontend build و TypeScript check موفق.
- اجرای قبلی schema v8 شامل ۴۹ تست `nabz-core`، ۲۴ تست backend Tauri و ساخت بستهٔ Arch بود؛ این اجراها شواهد نسخهٔ قبلی‌اند، نه تأیید تغییرات فعلی v10.
- اجرای تست فاز یک روی commit `21c02e9` به‌علت خطای compile در `LegacyMovement: Clone` شکست خورد؛ خطا در commit `04a0c36` اصلاح شد.
- پس از اصلاحات schema v10، import egui، backup/restore و گزارش‌های خالص، اجرای جدید CI هنوز در دسترس نیست؛ سبز بودن یا artifact جدید ادعا نمی‌شود.

## دیتابیس و مهاجرت

- شناسهٔ برنامه: `com.herotux.nabz.webprototype`؛ تا زمان برنامه‌ریزی مهاجرت داده تغییر نمی‌کند.
- مسیر Tauri در Linux: `~/.local/share/com.herotux.nabz.webprototype/nabz.sqlite3`.
- مسیر قدیمی egui: `~/.local/share/nabz/nabz.sqlite3`؛ جدا و دست‌نخورده باقی مانده است.
- قبل از هر migration دیتابیس موجود SQLite backup می‌شود.
- foreign keys، WAL، شاخص‌ها و transactionهای عملیات مالی فعال‌اند.
- در اولین اجرا، دیتابیس egui فقط اگر مقصد Tauri خالی باشد و integrity check مبدأ موفق شود، با backup و بدون دست‌کاری فایل مبدأ import می‌شود.
- فروش‌های egui به‌دلیل نبود وضعیت پرداخت در schema قدیمی به‌عنوان نقدی فرض می‌شوند؛ این فرض در یادداشت دریافت ثبت می‌شود.
- میانگین بهای افتتاحیه از `buy_price` قدیمی برآورد می‌شود؛ ردیف‌های فروش بدون `sale_item_costs` بدون COGS باقی می‌مانند.

## قابلیت‌های هستهٔ مالی

- میانگین موزون متحرک و ارزش‌گذاری موجودی بر مبنای `average_cost`.
- snapshot بهای تمام‌شدهٔ هر ردیف فروش و بهای خرید هر ردیف خرید.
- دریافت/پرداخت با FIFO، ماندهٔ افتتاحیه، پرداخت جزئی و اعتبار اضافه.
- الزام مشتری ثبت‌شده برای فروش اعتباری/جزئی و مجازبودن فروش گذری فقط با تسویهٔ کامل.
- برگشت فروش/خرید و ابطال امن با ثبت سابقه و جلوگیری از معکوس‌کردن فاکتور دارای گردش بعدی.
- تخصیص مستقل پرداخت‌ها به فاکتور، ماندهٔ افتتاحیه و پیش‌پرداخت در `payment_allocations`؛ ابطال نقدی در `invoice_voids` و بدون حذف payment.
- اصلاح موجودی با دفتر ثبت immutable.
- ثبت هزینه و گزارش سود/زیان.
- فرمان‌های Tauri برای ارزش‌گذاری موجودی، هزینه، سود/زیان، برگشت و ابطال ثبت شده‌اند.

## پشتیبان‌گیری

- `nabz-backup-v2` تمام جداول مالی و عملیاتی را نگه می‌دارد.
- بازیابی v1 قدیمی نیز پشتیبانی می‌شود.
- پیش از restore پشتیبان ایمنی SQLite ساخته می‌شود؛ validation، foreign-key check و integrity check پیش از commit انجام می‌شوند.

## محدودیت‌های تأیید

- برای کالاهای موجود در دیتابیس قدیمی، میانگین افتتاحیه از آخرین `buy_price` تخمین زده می‌شود؛ این تاریخچهٔ واقعی خرید را بازسازی نمی‌کند.
- فروش‌های قدیمی بدون snapshot COGS بدون حدس‌زدن باقی می‌مانند و در گزارش جدا هستند.
- نصب بسته روی Manjaro واقعی، حفظ داده پس از upgrade واقعی، چاپگر فیزیکی و بارکدخوان فیزیکی هنوز آزمون نشده‌اند.
- اتصال کامل فرمان‌های جدید برگشت/هزینه/سودوزیان به گردش‌های UI در فاز UI بعدی انجام می‌شود.

# وضعیت پیاده‌سازی نبض — React/Tauri

آخرین بررسی: 2026-11-17  
شاخهٔ مرجع: `ui/react-tauri-redesign` — PR شمارهٔ ۸ (Draft)

## وضعیت بیلد و انتشار

- مسیر فعال محصول React + TypeScript + Vite در پوستهٔ Tauri 2 است.
- CI فعال: `.github/workflows/tauri-web-ci.yml`؛ شامل build و type-check frontend، تست Rust/SQLite، ساخت باینری Tauri و بستهٔ Arch/Manjaro.
- نسخهٔ frontend، Tauri، Cargo و PKGBUILD روی `0.1.0` یکسان شده و CI این برابری را کنترل می‌کند.
- بسته‌بندی داخلی Tauri برای deb/AppImage غیرفعال است؛ خروجی هدف `.pkg.tar.zst` است.
- گردش‌کارهای قدیمی egui و Tauri prototype در این شاخه حذف شده‌اند.
- نتیجهٔ CI برای commitهای پاک‌سازی‌شدهٔ جدید هنوز باید از اجرای GitHub Actions خوانده شود؛ سبز بودن اجرای قبلی، اجرای commit جدید را تأیید نمی‌کند.
- نخستین اجرای CI پس از یکسان‌سازی نسخه‌ها (run `44076351325`) در مرحلهٔ کنترل نسخه شکست خورد؛ علت، نبودن ماژول `tomllib` در Python 3.10 پیش‌فرض Ubuntu 22.04 بود. کنترل نسخه بدون وابستگی به `tomllib` اصلاح شده و نتیجهٔ اجرای commit اصلاحی `9113f435` هنوز در دسترس نیست.
- نصب و اجرای بسته روی Manjaro واقعی هنوز تأیید نشده است.

## معماری و داده

- رابط فعال: React + TypeScript + Vite.
- پوسته و دسترسی داده: Tauri 2 + Rust + SQLite.
- شناسهٔ فعلی Tauri: `com.herotux.nabz.webprototype`؛ تا پایان مهاجرت داده نباید تغییر کند.
- مسیر دیتابیس Tauri در لینوکس معمولاً `~/.local/share/com.herotux.nabz.webprototype/nabz.sqlite3` است.
- دیتابیس قدیمی egui در `~/.local/share/nabz/nabz.sqlite3` قرار دارد؛ دو دیتابیس جدا هستند و مهاجرت خودکار هنوز انجام نشده است.
- کد egui در ریشهٔ مخزن فقط برای بررسی/مهاجرت احتمالی نگه داشته شده و workflow انتشار فعال ندارد.
- هستهٔ `nabz-core` از PR شمارهٔ ۵ هنوز به مسیر Tauri منتقل نشده است؛ انتقال آن نیازمند migration و تطبیق API است.

## قابلیت‌های پیاده‌سازی‌شده در کد (نه لزوماً تأییدشده در دستگاه واقعی)

- هشت صفحهٔ اصلی: داشبورد، طرف‌حساب‌ها، فاکتورها، دریافت و پرداخت، کالا و انبار، گزارش‌ها، چاپ و بارکد، تنظیمات.
- SQLite محلی و فرمان‌های Tauri برای ثبت/خواندن اطلاعات، گزارش‌ها، پشتیبان‌گیری و بازیابی.
- ثبت فاکتور در تراکنش SQLite، کنترل موجودی فروش و افزایش موجودی خرید.
- تخصیص دریافت/پرداخت به مانده‌های باز و ماندهٔ افتتاحیه، FIFO و اعتبار مازاد مشتری/تأمین‌کننده در پیاده‌سازی فعلی.
- اعتبارسنجی ساختار پشتیبان JSON پیش از بازیابی.
- تقویم شمسی و ارقام فارسی در بخش‌های پیاده‌سازی‌شده.
- تولید Code 128 و ورودی اسکنر USB/HID به‌عنوان ورودی صفحه‌کلید.
- پیش‌نمایش/چاپ مرورگر؛ چاپ مستقیم سیستم و سخت‌افزار واقعی تأیید نشده‌اند.

## شکاف‌های مهم حسابداری

- میانگین موزون متحرک و ثبت بهای تمام‌شده در لحظهٔ فروش هنوز در مسیر فعال Tauri ادغام نشده‌اند.
- برگشت فروش/خرید و ابطال با ثبت عملیات معکوس هنوز کامل نشده‌اند.

- آزمون کامل مانده‌ها، پرداخت جزئی، تخفیف خرید، سود تاریخی، برگشت و بازیابی دیتابیس واقعی لازم است.
